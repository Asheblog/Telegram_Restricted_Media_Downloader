# 实时监听：操作整合与记录整理

**日期**: 2026-07-12  
**状态**: Approved  
**范围**: WebUI 桌面端 + 移动端「活跃监听」列表与详情查看  
**无新增领域边界**: 不改 LiveWatch / TransferStore 领域模型；不新增 ADR；`CONTEXT.md` 无需更新（纯 UI 信息架构与交互整理）

---

## 问题

「活跃监听」当前把编辑、转发记录、下载记录、待抓评论区、删除全部平铺为行内按钮；转发记录弹窗列多、目标频道每行重复、事件文案过长；待抓/今日记录又用行内展开打断列表扫描。桌面与移动端同样分散，小屏更难操作。

## 目标

1. 主列表一眼能扫：谁在跑、今日怎样、去哪看记录。
2. 次要操作收进一个入口，不再并排 4–5 个按钮。
3. 三种详情（转发记录 / 下载记录 / 待抓评论区）共用同一详情壳，桌面 modal、移动 sheet。
4. 取消行内展开，列表不再被详情撑开。

## 非目标

- 整页换皮、侧栏导航改版、新建设计系统
- 桌面右侧抽屉（可后续演进）
- 批量操作、跨 watch 搜索
- 全局「下载记录」页 / 「下载与上传」页改版
- 无必要的新后端 API 或统计字段（优先用现有 `event_count` / `today_count` / `deferred_comment_count` 与现有分页接口）

---

## 决策摘要

| 项 | 选择 |
|----|------|
| 改造范围 | 操作整合 + 记录数据整理（桌面与移动） |
| 行操作 | 主按钮「记录 N」外露 + `⋯` 溢出菜单 |
| 记录面板 | 状态优先列表 + 顶部摘要 + 状态筛选 |
| 行内展开 | 全部取消，改弹层 / Sheet |
| 主列表密度 | 紧凑行（短频道名、状态点、今日数内联） |
| 实现路径 | 统一 `WatchDetail` 详情壳，三种模式共用 |

## 1. 主列表与操作

### 布局

每行展示：

- 状态点（运行中绿 / 暂停灰等，沿用现有状态语义）
- 类型文案（监听转发 / 监听下载）
- 「今日 N」（来自 `today_count`）
- 可选「待抓 N」徽标：仅当 `include_comment` 且 `deferred_comment_count > 0`（或有待处理项）时显示
- 短链路：`source → target`，展示时去掉 `https://t.me/` 前缀；完整 URL 用 `title` / 长按或点击查看
- 主按钮：`记录 {event_count}`（仅转发类；见下方类型分支）
- `⋯` 菜单

取消独立宽列：类型徽章列、完整 URL 列、状态文字列、今日独立列、多按钮操作列的并排堆叠。桌面可用「任务 | 操作」两列或等价紧凑表；移动端为同结构卡片。

### `⋯` 菜单内容

| 项 | 条件 | 行为 |
|----|------|------|
| 编辑 | 转发类（与现网一致） | 打开现有编辑流程 |
| 下载记录 | 转发类 | 打开 `WatchDetail` · downloads |
| 待抓评论区 | 转发且开启评论区 | 打开 `WatchDetail` · deferred；可显示数量 |
| 删除 | 全部 | 菜单底部分隔 + 危险色；保持现有二次确认 |

桌面：锚定行的下拉菜单。  
移动：底部 Action Sheet（含取消）。

### 类型分支

- **监听转发**：主按钮 = 「记录 N」→ `WatchDetail` · history；`⋯` 含编辑 / 下载记录 / 待抓（条件）/ 删除。
- **监听下载**：不显示「记录」主按钮；行上仅保留 `⋯`（内含删除；若后续为下载类补齐「下载记录」入口，也只进 `⋯`，不新增第三枚按钮）。与现网「下载类无编辑/转发记录」一致。

### 待抓徽标

- **菜单项「待抓评论区」**：`include_comment === true` 时始终显示（可附数量，含 0）。
- **行内「待抓 N」徽标**：仅当 `include_comment` 且 `deferred_comment_count > 0` 时显示，避免无待办时占位。
- 点击徽标与菜单项等价，均打开 `WatchDetail` · deferred。

### 明确移除

- 行内 `watch-events-panel` / `watch-deferred-panel` 展开
- 操作列上并排的编辑图标、下载记录、待抓、删除按钮

## 2. 统一详情壳 `WatchDetail`

### 壳结构（三种模式共用）

1. **标题**：按模式 —「监听转发记录」/「监听下载记录」/「待抓评论区」
2. **副标题**：短链路 `source → target`
3. **摘要条**：模式相关计数（如今日 / 全部；下载进行中·完成·失败；待抓各状态计数）
4. **可选筛选**：状态 chips（全部 / 成功 / 已过滤 / 失败等，按模式有无裁剪）
5. **内容列表**：状态优先行（徽章 + 短标题 + 次要元信息）
6. **底栏**：分页或行级操作（重试 / 取消等，沿用现有能力）

### 呈现

- 桌面：居中 modal（可复用/演进现有 `#watch-history-modal` 等容器，统一为一种壳）
- 移动：底部 sheet
- 同一数据渲染函数桌面/移动共用，仅外壳不同（符合 ADR-0005 桌面/移动统一契约方向）

### 模式：history（转发记录）

- 去掉每行「目标频道」列（目标已在副标题）
- 事件文案映射为短标题（例：转发成功、命中过滤关键词、转发失败）；完整原因默认折叠，点击行展开
- 状态徽章保留语义色，且不只靠颜色区分（有文字）
- 筛选：全部 / 成功 / 已过滤 / 失败  
  - 服务端按 `status=success|skipped|failure` 筛选并分页；响应带全局 `status_counts`（`all/success/skipped/failure`）供标签计数  
  - UI「已过滤」对应库字段 `skipped`；切标签重置到第 1 页并重拉
- 分页：沿用现有「第 x/y 页」交互；`total` 为当前筛选条件下的总数

### 模式：downloads（下载记录）

- 摘要：进行中 / 已完成 / 失败等（用现有任务字段）
- 列表行：状态优先 + 任务标识/文件名摘要
- 空状态沿用现有文案
- 行内删除等危险操作保持确认

### 模式：deferred（待抓评论区）

- 列表：消息 ID、状态、计划时间；行级「重试 / 立刻执行 / 取消」等保持现有权限与确认
- 筛选：待处理 / 已完成 / 失败（有数据再显示）
- 不再插入主表中间

### 入口映射

| 用户动作 | 打开模式 |
|----------|----------|
| 主按钮「记录 N」 | history |
| `⋯` → 下载记录 | downloads |
| `⋯` / 待抓徽标 → 待抓评论区 | deferred |

## 3. 移动端

- 列表卡片信息与桌面紧凑行同一信息架构
- 主按钮与 `⋯` 触控目标 ≥ 44×44px，间距 ≥ 8px
- `⋯` → Action Sheet；详情 → 全宽底部 Sheet
- 禁止主内容区横向滚动；长链路截断 + 可查看全文
- 筛选 chips 可横向滑动（仅 chips 行），列表本身纵向滚动

## 4. 实现要点（非实现计划）

涉及前端（预期）：

- `module/adapters/webui/static/desktop.js` — `renderWatches`、history/downloads/deferred 打开与展开逻辑
- `module/adapters/webui/static/mobile_script.js` — 对应卡片与 sheet
- `module/adapters/webui/templates/views.html` / `mobile_body.html` — modal/sheet 壳（如需合并容器）
- `module/adapters/webui/static/shared.js` — i18n 文案（菜单项、短标题、筛选）
- 样式：`tailwind` 构建源 / 相关 CSS（操作列、菜单、sheet）

后端：默认不改 API。若筛选必须服务端分页，再单开最小接口变更（超出本设计默认范围，需另批）。

测试建议：

- 转发 watch：记录主按钮、菜单四项、无行内展开
- 含评论区 watch：徽标与菜单均打开 deferred，可重试
- 下载类 watch：操作控件 ≤2，删除仍可用
- 记录弹层：无重复目标列；长原因可展开；分页仍可用
- 移动：Action Sheet / Sheet、无横向滚动、触控可点

---

## 5. 成功标准

- 活跃监听每行可见操作控件 ≤ 2（主按钮 + `⋯`）
- 三种详情均通过统一壳打开，主列表无行内展开
- 转发记录不再每行重复目标频道；默认短标题可读
- 桌面与移动信息架构一致，仅外壳（modal vs sheet）不同

## 附录：已否决方案

- 仅改操作列、不整理记录面板 — 解决不了「记录乱」
- 整页信息架构重做 / 整页换皮 — 超出痛点
- 单一「详情」入口（所有能力多点一次）— 压抑最高频的「看记录」
- 可点数字胶囊行 — 行高过大，76 条列表不适合桌面
- 保留待抓行内展开 — 继续打断扫描
- 桌面右侧抽屉 — 体验好但首版成本高，留作演进
