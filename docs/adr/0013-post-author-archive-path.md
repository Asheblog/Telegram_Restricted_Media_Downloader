# Nest PikPak archives under Post Author (opt-in)

部分频道主贴正文含作者署名行（完整标记 `…作者：#名字`，或频道常见短形式 `作者：#名字` / `作者：@名字`），但并非所有频道如此。我们选择：默认 Source Post Archive Path 保持扁平 `{Source Channel Folder}/{message_id} - {正文摘要}`；转存任务与监听规则增加可选开关 `archive_by_author`（默认关），勾选后路径扩展为 `{Source Channel Folder}/{Post Author}/{message_id} - {正文摘要}`，抽不到作者时落 `_未知作者`。新转存按任务/规则开关写入；历史扁平目录仍可由 WebUI「归档整理」显式抬升（与实时开关解耦）。频道统计仍只按路径第一段聚合。

历史整理另增分层置信度：署名/相册为高置信自动搬；署名行若出现多个标签（如 `作者：#海角社区 #翘臀巨乳小妈`）则跳过站点/主题黑名单后取真实作者——禁止把 `海角社区` 当作者，但接受上传者 UID `海角_<数字>` 作为作者目录。无署名时提取 hashtag（含相册兄弟消息 caption 与 hashtag entity）：命中频道可信作者集合（本次署名命中 ∪ 网盘已有作者目录，排除 `_未知作者` 与主题黑名单）时——精确可自动搬，近似/子串进「待确认」；若过滤后只剩一个非站点作者样标签，则进「待确认」作标签候选（`hashtag_candidate`），不因陌生而直接丢进未识别。UI 提供迁移一览汇总 + 分页明细；「全部迁移」一次执行高置信与待确认，未识别默认不搬。「未识别 → `_未知作者`」为独立动作（`execute_mode=review`），把确无作者或仍无法识别的主贴夹显式迁入 `_未知作者`，避免未识别永久卡死。「仅解析未识别」复用上次计划中已识别作者（站点名误标不保留），只回查 `needs_review` / `_未知作者` / 黑名单误标主贴，避免全量重拉 Telegram。

**Considered Options:** 全局默认按作者（误伤无署名频道）；按频道记忆勾选；仅整理历史不改新路径；抽不到作者时保持扁平（即使已勾选）；把任意 hashtag 当新作者自动建夹；待确认逐条点选批准；把未识别并进「全部迁移」（否决：易把暂时未解析到的帖误塞未知作者）。

**Consequences:** 需从正文解析作者署名行；rclone 需列目录并移动整夹；TransferStore 的 `source_folder` 在整理时尽量回写；不回填更早的无主贴目录散文件。历史整理必须串行慢速（Telegram 逐条拉取、rclone 列表/移动带间隔）。网盘列目录与 Telegram 作者解析分离：目录清单可复用，「重新解析作者」只按主贴 ID 回查 Telegram 并重建计划，禁止为了改作者再全量扫网盘；整理复用最近一次成功扫描/解析计划。公共 Job 视图只返回汇总，明细走分页 API。实时链路默认扁平，避免无署名频道大量 `_未知作者`。已迁入作者夹或 `_未知作者` 的目录再扫会标 `skip_already`，不必为「迁完」强制重扫。
