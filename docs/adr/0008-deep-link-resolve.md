# Deep link resolve before transfer

部分频道帖只含资源 bot 的 `t.me/<bot>?start=` 深链而非可直接转发的媒体。我们选择：任务/监听勾选 `resolve_deep_link` 且全局白名单非空时，用**用户会话**（`messages.startBot`）向白名单 bot 取回 `video`/`document`/`animation`/`photo`，再对取回消息走既有转发→下载上传链路；命中白名单深链时以 bot 回传为准，**不回退**频道预览；取片失败即失败。开启深链后若消息**无**白名单深链，则**跳过**原帖封面/预览（Web 记 SKIPPED，监听记 skipped），不把频道封面标为提取成功；真资源依赖评论区延迟抓取（双开「包含评论区」）。全局 `deep_link.bot_whitelist` 限定可解析 bot；**串行**取片，默认超时 60s（可配），默认最小间隔 30s（可配），默认收齐静默 3s（可配）：首条媒体后继续收集直到静默窗口或超时，以覆盖资源 bot 连发多文件。取片过程中若 bot 私聊出现 inline 翻页/组别按钮，则自动点击（`messages.getBotCallbackAnswer` / Pyrogram `request_callback_answer`）并继续收齐：优先未点过的组别按钮，否则点「下一页」；忽略「上一页」与页码状态钮；已在末页（如 `2/2`）则不再点下一页；零媒体但已有可点按钮时也允许起翻。翻页共用同一 `timeout_seconds` 预算，另受 `max_pages`（默认 20）与 `page_click_interval_seconds`（默认 1）约束。翻页点击失败时保留已收媒体并继续转存（warning），不因后续页失败整单作废。若 bot 回传业务会话失败文案，则按硬/软标记处理：硬标记（「会话已超时关闭」「会话超时」）无论是否已有媒体均整波作废；软标记（「会话已关闭」「会话已退出」）仅在本波无媒体或仅有 photo（预览）时作废并重试，已有 video/document/animation 时视为正常收尾并保留（避免 3b37e9c 误伤）。作废后在 `min_interval_seconds` 后再次 `StartBot`；同一次 resolve 最多 3 次 StartBot，每次各自使用完整 `timeout_seconds`；耗尽后失败，不把预览图当成功。同一轮历史先收媒体再判会话文案，避免 video 与收尾文案同批时软标记误触。此路径与「翻页失败保留已收媒体」不同——会话超时是整单无效。翻页/组别按钮只从本次 StartBot 之后的消息选取；已有媒体时翻页无新媒体则停翻保留结果，零媒体时则继续等到总超时，避免误点历史菜单后提前报「未返回媒体」。PikPak 归档与 Transfer Item 来源仍归属**原频道帖**的 Source Post Archive Path（见 ADR-0011），不改成 bot 会话文件夹。

评论区深链：同时开启 Discussion Reply Inclusion 时，讨论回复（含延迟抓取）**仅**处理含白名单深链的评论并 resolve；不附带按 `forward_type`/`check_type` 转存其它闲聊或媒体。未开深链时评论区仍按原 `check_type` 过滤。监听转发与 Web 转存共用此规则。主贴无深链时不会在主贴瞬间主动嗅探评论（依赖「包含评论区」+ 延迟抓取，避免竞态）。

**Considered Options:** Bot API 代点 start（无用户私聊上下文）；并行多 bot 取片；取片失败回退频道媒体/预览；自动加频道/讨论群或点验证按钮；FloodWait 必须等满 Telegram 秒数再失败（否决：长限流会占死串行锁）；主贴无链时自动硬扫评论区（否决：与延迟抓取竞态）；翻页失败整单失败（否决：已收组不应作废）；翻页单独超时预算（否决：与串行锁时长耦合，统一用总超时更简单）。

**Consequences:** 需维护白名单、超时、最小间隔、收齐静默、最大页数与翻页间隔配置；勾选但白名单空时创建任务/监听应拒绝；bot 私聊消息不自动清理；评论区资源需双开「包含评论区」+「深链取片」；长 `FloodWait` 会令当前项快速失败而非无限阻塞后续取片；按钮文案启发式可能漏识别非标准翻页 bot（可后续加配置正则）；会话失败文案为代码内置列表，未覆盖的 bot 变体句需改代码；会话超时自动重试最多 2 次会拉长串行取片占用时间（含冷却）；默认「图片浏览」类 bot 若真资源在「视频」模式按钮后，仍需后续扩展模式切换点击。
